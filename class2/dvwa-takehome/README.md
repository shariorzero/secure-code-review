# ঐচ্ছিক টেক-হোম: DVWA-তে SQL Injection-এর সোর্স তুলনা

**সময়:** ২০–৩০ মিনিট · **কখন:** Class 2-এর ORM injection ল্যাব শেষ করার পর · **ঐচ্ছিক**, মূল ল্যাব আমাদের নিজের Node.js ও Django ফাইলেই।

**উদ্দেশ্য:** একই বাগ (SQL injection) চার স্তরে কীভাবে বদলায় তা পড়ে দেখা, তারপর Django-র ORM injection-এর সাথে মেলানো। এখানে কোনো হ্যাক করা লাগবে না, শুধু কোড পড়া।

> ⚠️ DVWA ইচ্ছাকৃতভাবে দুর্বল। শুধু নিজের মেশিন বা নিজের Codespace-এ চালান। কখনো ইন্টারনেটে খোলা সার্ভারে ইনস্টল করবেন না। অফিশিয়াল রিপো: `github.com/digininja/DVWA` (শুধু সর্বশেষ অফিশিয়াল সংস্করণই supported)।

## পথ ১: চালিয়ে দেখা (Docker থাকলে)

DVWA-র README অনুযায়ী (নিজে একবার মিলিয়ে নিন, ধাপ বদলাতে পারে):

```bash
git clone https://github.com/digininja/DVWA.git
cd DVWA
cp config/config.inc.php.dist config/config.inc.php
docker compose up -d
```

ব্রাউজারে `http://localhost:4280` খুলে **Setup DVWA** থেকে **Create / Reset Database** চাপুন। ডিফল্ট লগইন `admin` / `password`। **DVWA Security** মেনু থেকে স্তর (Low, Medium, High, Impossible) বদলান।

## পথ ২: শুধু কোড পড়া (Docker না থাকলে, এতেই কাজ হয়)

DVWA-র রিপোতে `vulnerabilities/sqli/source/` ফোল্ডারে চারটি ফাইল আছে: `low.php`, `medium.php`, `high.php`, `impossible.php`। GitHub-এ এগুলো খুলে পাশাপাশি পড়ুন।

## কাজ

1. SQL Injection মডিউলে "View Source" খুলে Low স্তরের কোডে **৩টি প্রশ্ন** করুন: ইনপুট কোথা থেকে? বিপজ্জনক জায়গা কোনটি? মাঝখানে পাহারা আছে কি?
2. Medium, High, Impossible স্তরের কোড একে একে দেখুন (সম্ভব হলে "Compare All Levels")।
3. Low আর Impossible পাশাপাশি রেখে দেখুন কোন কোন লাইন বদলেছে।

## ৫ লাইনে লিখুন (জমা দেওয়ার ছক)

1. **Low:** ইনপুট কোথা থেকে এসে কোন লাইনে বিপজ্জনক হচ্ছে?
2. **Medium:** কী বদলানো হয়েছে? এতেই কি পুরোপুরি নিরাপদ হলো? কেন বা কেন নয়?
3. **High:** আরও কী বদলেছে?
4. **Impossible:** কোন পরিবর্তনে বাগ বন্ধ হলো?
5. **Django-র সাথে মিল:** এই বদলটি Django-র কোন কোডের সাথে মেলে? (`raw(f"...")` বনাম `filter(...)` বা `raw("... %s", [q])`)

## ইন্সট্রাক্টরের জন্য উত্তরের দিকনির্দেশ

- **Low:** ইনপুট সরাসরি SQL স্ট্রিংয়ে বসে, কোনো যাচাই নেই।
- **Medium:** ইনপুটে escape ফাংশন আছে, কিন্তু আইডি সংখ্যা বলে কুয়েরিতে কোটেশন নেই। escape থাকলেও বাগ থেকে যেতে পারে। **ক্লাসের আগে নিজে সোর্স পড়ে নিশ্চিত হোন**, কারণ এই বিবরণ আমি একটি তৃতীয়-পক্ষের ডকুমেন্টেশন সাইট থেকে পেয়েছি, DVWA-র কোড নিজে খুলে দেখিনি।
- **High:** ইনপুট নেওয়ার পথ বদলেছে (সেশন-ভিত্তিক), একই ডকুমেন্টেশন অনুযায়ী।
- **Impossible:** প্রিপেয়ার্ড স্টেটমেন্ট (`?` প্লেসহোল্ডার), সাথে Anti-CSRF টোকেন চেক। এটিই মূল শিক্ষা: ইনপুট আলাদা পাঠানো হয়, SQL কমান্ডের অংশ হয় না।
- **Django-র মিল:** `?` প্লেসহোল্ডার হলো Django-র `%s` প্লেসহোল্ডার বা `filter(username=q)`-এর মতো। Low-র কোড হলো আমাদের `raw(f"...{q}...")`।

**ভালো উত্তরের লক্ষণ:** শিক্ষার্থী শুধু "কোড বদলেছে" লেখে না, বলে *কেন* সেই বদল ইনপুটকে কমান্ড হতে দেয় না।
